# efb-summary-middleware

EFB 中间件：记录指定群聊的消息，每 X 天把最近 Y 天、最多 Z 条聊天记录交给 OpenAI 兼容接口总结，由 Telegram 主端的 bot 发到该群在 Telegram 里绑定的群组或话题。也可以在话题里发 `/summary` 随时汇总。

另外带一个 `/ask` 命令：用同一个模型简短回答一个问题，你在 Telegram 里审核通过后，以你的名义发到对应的微信群或私聊，见下文“/ask 问答”。

模块 ID：`specialhua.summary`

## 启用

```bash
source ~/efb-venv/bin/activate
pip install -e ~/oh-my-efb/summary-middleware
```

在 `~/.ehforwarderbot/profiles/default/config.yaml` 里加上：

```yaml
middlewares:
  - specialhua.summary
```

## 配置

`~/.ehforwarderbot/profiles/default/specialhua.summary/config.yaml`，含 API key，权限设为 600：

```yaml
base_url: https://example.com/v1   # 写到 /v1 为止，会自动拼上 /chat/completions
api_key: sk-xxxx
model: gpt-4o-mini

# 默认值，对下面所有群生效
interval_days: 3       # X：每 X 天自动汇总一次
lookback_days: 3       # Y：只取最近 Y 天的消息
max_messages: 10000    # Z：最多取最近 Z 条
# retention_days: 30   # 可选：消息保留天数，见下文“数据”

chats:                 # 要总结的群：群名、备注名或 chat ID，任一匹配即可（/ask 不受这里限制）
  - 某个群             # 只写名字：全部用默认值
  - name: 另一个群     # 写成映射：单独覆盖上面任意几项
    interval_days: 5
    lookback_days: 5
    max_messages: 2000
  - name: 第三个群
    lookback_days: null   # 写 null 取消默认的天数限制，只按条数取

# 以下可选
# prompt: |            # 覆盖内置的系统提示词
#   ...
# max_chars: 40000     # 单次请求的聊天记录字符上限，超出则分段总结再合并
# timeout: 180         # 单次请求超时（秒）

# ask:                 # 可选：/ask 默认开启，沿用上面的 base_url、api_key、model
#   max_chars: 150     # 回答最多多少字；需要展开的问题会尽量用足，简单问题仍会简短
#   model: gpt-4o-mini # 单独换一个模型
#   prompt: |          # 覆盖内置提示词，其中的 {max_chars} 会换成上面的字数
#     ...
#   timeout: 60        # 单次请求超时（秒）
# ask: false           # 关闭 /ask，此时 /ask 会当成普通消息发出去

# jev:                 # 可选：用 TypeSafe 的 Jev 给消息分类，总结前筛掉无用消息，见下文“行为”
#   api_key: ts-xxxx
#   model: jev-latest  # 默认 jev-latest；也可以写 jev-preview 或具体版本
#   # lang: zh         # 问 Jev 的问题用中文（zh）还是英文（en）
#   # min_confidence: 0.6  # 附和/闲聊/广告要有多大把握才筛掉
#   # highlight: 0.2   # 每次总结里把最值得提的前百分之多少标 ★，0 为不标
#   # base_url: https://api.typesafe.ai/v1
#   # timeout: 60
```

只用 `/ask` 不需要总结时，`chats` 可以不写。每个群必须有 `interval_days`，并且 `lookback_days` 和 `max_messages` 至少有一个（来自默认值或自己的设置都算）。没有配置文件或这些条件不满足时，EFB 会在启动时直接报错退出。

配置文件改动后不用重启：中间件每分钟检查一次文件是否变化，手动触发汇总前也会检查，变了就重新读取，所有配置项（包括增减群）都即时生效。新文件有错误时会发消息告知原因，并继续使用之前的配置。

### 用 Jev 试标消息

配好 `jev` 之后，中间件就会自动分类、在总结时使用（见“行为”）。也可以先离线看看 [Jev](https://docs.typesafe.ai/introduction) 给已记录的消息分类分得准不准，再决定是否用于总结。脚本只读数据库，EFB 不用停：

```bash
~/efb-venv/bin/python -m efb_summary_middleware.jev_trial                       # 列出库里的群
~/efb-venv/bin/python -m efb_summary_middleware.jev_trial --chat 某个群 --limit 200
```

每条消息会结合前后的消息判断一个类别（安排/通知、提问、回答、信息/资料、观点、附和/闲聊、广告、其他），以及总结时“值得提”的概率。只有图片、表情等占位符的消息由代码直接标为“媒体”，不发给 Jev。输出里 ✂ 是可以剔除的（媒体，或有把握的附和/闲聊/广告），★ 是其余消息里最值得提的一部分，最后统计各类数量、剔除比例、“值得提”的分布和花费。常用参数：

- `--lang en`：问题用英文写（消息原文不变），和默认的中文对比效果
- `--model jev-preview`：换模型版本
- `--min-confidence 0.6`：多高的把握才算确定，低于它的类别会同时显示第二候选，后面带 `?`
- `--highlight 0.2`：在群内排名前多少的消息标 ★
- `--batch 30 --before 20 --after 5`：每个请求标多少条、前后带多少条做上下文
- `--out labels.jsonl`：把结果另存一份，方便对比

## /ask 问答

在任何一个微信群或私聊对应的 Telegram 话题（或绑定的群组）里都能用，不需要在 `chats` 里配置：

- `/ask yandex是什么`：回答这个问题
- 回复群里的某条消息发 `/ask`：回答那条消息里的问题；发出时会引用那条消息
- 回复某条消息发 `/ask 问题`：把那条消息作为上下文来回答

被回复的消息要是从微信转到 Telegram 的那种（bot 发出的），它的内容会一起交给模型：文字、链接的标题和地址，以及图片和表情本身。只有图片没有文字时，直接回复 `/ask` 会默认问“这条消息说的是什么？”。图片要求模型支持识图（如 gpt-4o-mini）；模型读不了图片、图片超过 5 MB 或已无法从 Telegram 下载时，就只按文字回答，审核消息里会注明。

命令本身不会发到微信。bot 会先回一条“正在回答”，生成后变成问题加答案，下面带按钮：

- **✅ 发送**：以你的名义把答案发到微信，审核消息变成“已发送”
- **✏️ 填入输入框**：把答案放进 Telegram 的输入框，改好后自己发。Telegram 会在前面带上 `@bot用户名`，发出时会自动去掉。答案超过 256 字时没有这个按钮（Telegram 的上限）
- **🔄 重新生成**、**❌ 取消**

只有 ETM 的管理员能按这些按钮。答案长度靠提示词控制（默认 150 字以内），模型偶尔会超出，发送前可以看到字数。审核中的答案只保存在内存里，EFB 重启后或一天后按钮会失效，重新 `/ask` 即可。

说明：Telegram 的 bot 不能冒充你在 Telegram 里发消息，所以 Telegram 里看到的始终是 bot 那条审核消息；“以你的名义”指的是在微信里由你的账号发出，和你在 Telegram 里直接打字发到微信是同一个效果。

问题、群名和被引用的消息（包括图片）会发送给 `base_url` 指向的服务。

## 行为

- **周期**：每个群各自计时，从首次启动起每满 `interval_days` 天汇总一次。上次汇总时间按群存在数据库里，重启不会打乱周期；停机期间错过的会在启动后约一分钟补发。
- **窗口**：每次取“最近 `lookback_days` 天之内”的消息，其中最多取最新的 `max_messages` 条；两项只设一项时就只按那一项取。实际记录不够时有多少总结多少。不记录哪些消息已经总结过，所以窗口比周期长时相邻两次会重叠，比周期短时中间会有消息不被总结。
- **在话题里汇总**：在群对应的 Telegram 话题（或绑定的群组）里发命令，结果回复在同一处。命令本身会被拦下，不会发到微信群。
  - `/summary`：按该群配置的范围汇总
  - `/summary 7` 或 `/summary 7天`：最近 7 天，仍受该群 `max_messages` 限制
  - `/summary 500条`：最近 500 条，不限天数
  - 参数写错时回复用法；在没配置总结的群里发会回复提示。两种情况都不会发到微信群。但命令名打错（如 `/sumary`）会被当成普通消息发出去。
- **在私聊里汇总**：发 `/extra` 找到“立即汇总”对应的命令（形如 `/1_summary`）。不带参数汇总所有群，`/1_summary 群名` 只汇总一个（群名按配置里写的填），结果发到私聊。
- **以上手动方式都不影响定时周期。**
- **发到哪**：定时汇总发到该群在 Telegram 里的位置：绑定了群组就发到群组，走话题分流就发到它的话题。找不到位置（比如还没收到过这个群的消息）或发送失败时，改发到管理员私聊。
- **输出**：一条 Telegram 消息；超过长度上限时消息只放前半部分，完整版作为 `.html` 附件跟在后面。
- **失败**：单次请求自动重试 3 次；定时汇总失败后每小时再试一次，只在第一次失败时通知。
- **非文本消息**：记为 `[图片]`、`[语音]` 等占位；链接保留标题、描述和地址。
- **用 Jev 筛选**（配了 `jev` 时）：后台每分钟给新消息分类，一条消息要等后面来了 5 条，或者过了 10 分钟才分，这样能结合前后文判断；汇总前会把剩下的也分完。总结时：
  - 省略只有图片、表情等占位的消息，有把握的附和、闲聊、广告，以及重复出现的长消息（15 字以上），记录开头注明省略了多少，标题下的统计显示“筛掉 N”
  - 剩下的消息标上〔安排〕〔提问〕〔回答〕〔信息〕，其中最值得提的前 `highlight` 标 ★，并在提示词里说明这些标记，让模型优先覆盖
  - Jev 出错时，没分类的消息照常进入总结，只是不筛选；连续出错只通知一次
  - 刚启用时，库里已有的消息会分几轮补完，每轮每个群最多 300 条。费用按输入计，每 1000 条消息约 $0.04
- **数据**：消息存在同目录的 `messages.db`，每次汇总后清理。默认设了 `lookback_days` 的群保留 `lookback_days + 7` 天，只设 `max_messages` 的群保留最新的 `max_messages` 条。`/summary 30` 这类命令只能汇总到还保留着的消息，想回看得更久就设 `retention_days`，设了之后一律按这个天数保留。只有启用之后收到的消息才会被记录。

聊天记录会原文发送给 `base_url` 指向的服务。
